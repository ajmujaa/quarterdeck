Features

Four things and nothing else: a project, a crew member, a duty and a run. New capability means adding one of these, not editing the machinery.

Words used here

Project
A repository you have registered, with its guardrails and the command that proves a change works.
Crew
The built-in agents. Each is a short markdown file describing one point of view.
Duty
One script that does one job, such as reviewing a pull request.
Run
One execution of a duty, with a one-line verdict kept in the ledger.
Ledger
The record of every run, what it cost and what it said.

Review and build duties

  • surveyor reads a pull request and posts findings as review comments.
  • marshal reads a pull request for security.
  • joiner reviews the interface: accessibility, states, responsive behaviour.
  • inspector checks that a pull request does what it claims.
  • shipwright takes one issue to a branch and a pull request, in a throwaway worktree.
  • trials writes the test that reproduces a bug and proves it fails first.
  • caulker fixes exactly the problem that was found.
  • assayer writes tests, as a different agent from the one that built the change.

Backlog and upkeep duties

  • foreman turns a findings document into well-formed, deduplicated GitHub issues.
  • purser turns a backlog issue into something a stranger could start cold.
  • planner turns the open backlog into a sprint plan you read.
  • harbourmaster keeps the project board honest about what is actually happening.
  • scribe drafts the README and architecture overview a project is missing, and puts them on a new branch only when you say so.
  • bosun reports drift: stale branches, dead settings, docs that name things that are gone.
  • quartermaster checks what comes in: dependencies and what they actually are.
  • infra reads Terraform, CDK, CloudFormation, SAM, serverless, Vercel and Supabase files and reports risk and how to undo a change. It runs nothing against a cloud and holds no credentials.

Beyond single duties

One bounded cycle

qtdeck cycle <project> --issue <n> takes one issue through requirements, a plan, a build, tests written by a different agent, five reviewers side by side and a capped number of fixes. Then it stops for you to read the pull request and merge it. It is off unless the project opts in, report-only unless you pass --apply, resumable, and it stops before any stage that would cross your daily or per-run budget.

Sprint planning you approve

The planner writes an order that respects dependencies, a size (S, M or L) with a reason for each item, what needs a decision from you first, and what to leave out. Cost is the number your own finished runs measured, or plainly "unknown" when there are none. Nothing on your board changes until you run qtdeck plan approve.

A brief and mock-ups you approve first

An idea becomes a one-page brief in plain words, with what it assumed and what only you can answer. After you approve it, one static page is made per screen. The harness checks each page against an allowlist (no script, no external address, visible keyboard focus, readable contrast) and shows it only in a sandboxed frame.

Panel

Several crew members look at one question and are made to disagree before a chair rules.

The Brain

One map of your projects, your agents and the services you connect. It is built from what you have added, so adding or removing a project or a connection changes it with no code edit. Click any dot to see what it is, what state it is in and where it leads.

Connections

Gmail or Mac Mail, team chat, web analytics, post numbers for Facebook, Instagram, LinkedIn, Threads and X, and your Mac's calendar and reminders can be shown in the Brain. Each is a small script that calls the service's own API with a read-only credential, with no model in the path. A credential you enter goes into a private file on your computer and is never shown again. Quarterdeck never posts to a social account. Nothing is claimed as tested against a real service unless that service's file says so.

Calm mode

A switch in the top bar. It shows larger text in one column and only what needs you, and folds the rest behind Show everything. It starts on by itself if your system asks for reduced motion.

Packs

A pack is a short note about one stack that the crew reads before it works on a matching project. The python and typescript-node packs carry no tag. The six infrastructure packs (aws, vercel-supabase, azure, google-cloud, cloudflare, fly) are labelled experimental: they were tested on small examples only, and every infra report says so in its footer. Read such a report as a second opinion, not a verdict.

Helm, the optional voice

An assistant you can talk to and listen to. It is off until you set it up, and the rest of Quarterdeck works without it. Speech recognition (whisper.cpp), the voice (Kokoro) and the small language model that answers (llama.cpp) all run on your machine. Helm can optionally think with Claude for open questions; that is off by default, capped per day, never on in demo mode, and you choose what it may be told.

Your data stays yours

The program and your data are separate folders. Your registry, runs, notes, logs and settings live in your data folder, ~/.quarterdeck by default. You can update or delete the program without touching your data.
